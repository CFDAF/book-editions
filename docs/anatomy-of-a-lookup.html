book_editions · a recap of the machinery

Anatomy of a Lookup

You type a title in any language and press Look up. Forty seconds later you get a publication history. This is every route the request can take in between — and why almost every rule in the code exists to stop a catalogue from answering confidently and wrongly.

01The
premise

The question it answers

Give it a title in any language. It shows when the work first appeared, and every edition since, grouped by language, with where to get a copy.

That single view answers four things at once: when the work was originally published and in what language; whether a translation exists and how long it took to arrive; which editions exist, from whom, in what year; and where you can actually buy or borrow one.

Only the second is the reason the tool exists. The handoff records the user's own framing —

discover a book, then find out whether an Italian translation exists before deciding which one to buy

HANDOFF.md §1

Italian is where the engineering went, because Italy has a good national catalogue (SBN) and no public API for it. But Italian is data focus, not framing: it is displayed as one language among the rest, and the lookup works from either end — the original title or the translated one.

Design rule

The header is a publication history, not a verdict. An earlier version led with “Translated into Italian.” and the user rejected it outright: it answers one narrow question and buries what the editions actually tell you. Re-adding a yes/no hero is a regression in intent, not a feature.

There is a second, separate question the tool also answers: give it an author and no title, and it returns their whole bibliography — one row per work rather than one row per edition. That runs down a different pipeline entirely, and the first branch in the code is the one that decides which question you asked.

02The
route

The route a request takes

There are two front doors and they meet almost immediately. The CLI calls lookup() directly. The browser cannot: SBN sends no Access-Control-Allow-Origin header of any kind, so a static page can never call it. The Python server is forced, not chosen — it exists to put the UI and the JSON on one origin.

FORKTwo questions, two pipelines

The very first statement inside lookup() is the mode switch. An author with no title is a different question — every book they wrote, not every edition of one book — so it delegates to lookup_author() and returns. That path pulls up to 200 Open Library works, keys them by normalised title, sweeps SBN for the author at rows=500, keeps one representative record per distinct title so the enrichment budget buys titles rather than duplicate copies, and merges. Wikidata is marked skipped (not needed for an author search).

Everything else in this document describes the title path.

03The
gap

The problem underneath everything

Almost every design decision in this project follows from one measurement:

title_similarity('Noise', 'Rumori')  →  0.0

A work and its translation share no words. There is no text-matching route from an original to its translation, in either direction, ever. Something other than the title has to carry the identity across the gap — and the four things that can are what the codebase calls bridges.

Precision and recall, as the handoff records them

SBN uniform-title authorityexact — the catalogue's own statementneeds SBN to hold and link the record

Dewey works as a bridge for one reason: it is numeric, hence language-neutral. Bruits carries 780.07 in Open Library and SBN's Rumori carries 780.07 — an exact match between two titles sharing not one word. And the same test has the symmetric virtue of correctly declining: Attali's Quale socialismo, quale Europa is Dewey 335, same author, same year, different book.

The fourth bridge was found last and is the strongest. It is also the only one that reaches a book with no Wikipedia article, no shared ISBN and no Dewey class at all — which is exactly how it was discovered. That story is §06.

04The
phases

The five phases, in order

The steps are numbered in the source. There is no step numbered between 2 and 4 by accident — slot 3 was Google Books, which was removed, and SBN's work authority later moved in.

PHASE 1Wikidata — the only source of an original language

Despite the name, there is no SPARQL anywhere. The whole phase is the MediaWiki Action API. The title is looked up as a page on the Italian and English Wikipedias concurrently, redirects followed, and the wikibase_item page property gives a QID. If no page matches, a list=search query supplies up to four candidates instead. Every candidate QID then goes into one batched wbgetentities call — fetching them one at a time used to cost about 38 seconds per cold lookup.

Endpoints
it|en.wikipedia.org/w/api.php · www.wikidata.org/w/api.php
Claims read
P31 instance-of, checked against 15 work classes so a person or a film is not mistaken for a book · P50 authors · P655 translators · P1476 original title · P407 original language · P577 publication date
Returns
a TitleCluster and the ISO code of the language the question was asked in

P407 and P577 are the only place any free source states what language a work was written in. That single fact is what makes an Italian-first lookup answerable at all. Cross-language titles come from Wikidata labels first and sitelinks only as a fallback, because sitelinks carry disambiguators — the Italian sitelink for Q208460 is 1984 (romanzo), the label is 1984.

Wikidata is also the only step that hands back an author for free, which turns out to matter enormously in phase 2.

PHASE 2Open Library — editions, Dewey, and titles it never asked for

Three query shapes are fanned out per title variant (title=variant, title=core_title(variant), and a free-text q), because Open Library's title= will not match a title carrying its subtitle: Noise: The Political Economy of Music returns zero documents while Noise returns the work. The winning works are then expanded into full edition lists and their Dewey classes fetched.

Two side effects of this phase are load-bearing:

Author back-fill

If Wikidata knew nothing, author is still None — and every author-keyed bridge below would be skipped: no SBN author sweep, no sibling titles. So the authors of the matched Open Library works are adopted, but only if all the matched works agree on one. A title as ambiguous as Noise resolves to several unrelated works, and taking whichever came back first would sweep SBN for a bibliography at random.

The second is stranger: italian_siblings() asks Open Library for the Italian titles of other books by this author. Those are never results. They are only query strings to throw at SBN, because SBN may file this book's translation under a title that no source has recorded as a translation of anything.

PHASE 3SBN's work authority — the catalogue stating it outright

This is a POST to a completely different SBN API (§06), and what it reads back is a facet named titolo_uniformef[] — SBN's UNIMARC uniform-title authority. That is a cataloguer's explicit statement of which work a record is an edition of. Searched with a title and an author, the top facet item by record count is the work's own title.

QueryTop facet valueShare
Più brillante del sole + Eshunmore brilliant than the sun1/1

One request answers what the other three bridges approximate. Two details govern how the answer is used. Film and TV adaptations are stripped from the facet before the winner is picked, so nome della rosa <serie tv ; 2018> cannot win. And the value that comes back is normalised — lowercased, de-accented, sometimes with trailing punctuation (cien anos des soledad. -). It is a search key, not a display string: it is good enough to find the work in Open Library, and the properly spelled title comes back from there. It is never shown to the reader.

Trap

opac.work_for must never be called without an author — and the guard is the first line of the function. Bare Rumori is 880 records whose top facet value is Russolo's arte dei rumori; Attali is not in the top five. Bare The Essential Knuth confidently returns essential mathematics for economic analysis, a different book entirely. It does not fail. It answers.

When the answer would be a guess — no author, no facet, only adaptations, zero records — it returns None. And a uniform title in Italian for an Italian book (Il nome della rosa → nome della rosa) is a correct answer meaning “not a translation”, not a failure.

PHASE 4SBN — the expensive part

Now the tool goes looking for actual editions. It builds a probe list and runs it six threads wide: up to 12 ISBN probes, one probe per title variant, up to 10 sibling-title probes, and an author sweep at rows=500. That sweep is why everything downstream needs a gate — it returns the author's entire catalogue.

Every candidate is then prescored on brief data alone. And brief data is the whole problem:

The brief record carries no language and no Dewey class — the two fields on which the entire rest of the pipeline depends. So every candidate worth considering costs a second HTTP request. That is the whole reason ENRICH_BUDGET = 150 exists, and why the prescore has to be good: it decides which 150 of sometimes ~700 candidates get fetched.

Once a record is enriched, four things happen to it: a self-contradicting language is neutralised, Dewey affinity is added to its score, a confidence level is assigned, and the gate decides whether it belongs at all (§05).

PHASE 4bWorking backwards, when nothing found an original

This only fires if the earlier phases produced no cluster. Two routes are tried in order.

The first uses SBN's uniform title as a search key into Open Library, takes the top two work keys, and synthesises a cluster marked sbn-authority. The second works from Italian SBN records that carry both authors and a Dewey class: for up to three such records it searches Open Library by each credited author, keeps only works whose Dewey agrees and whose credited authors are a superset of the Italian record's surnames, and takes the earliest as the original.

Two disciplines

Every credited author must match — 616.89 is the whole of psychiatry, which is what keeps Ruesch's unrelated Therapeutic communication out of a lookup for La matrice sociale della psichiatria. And it runs per record, never pooled: two SBN records can share an Italian title and be different books — that exact title is Ruesch/Bateson in 1976 and Michael Shepherd in 1990 — so pooling their authors would demand a work by all three and find nothing.

Both routes refuse to assert an original year that postdates the earliest translation found. An impossible arithmetic means the year is wrong, so it is dropped rather than shown. Results from this phase are flagged inferred in the interface, in red, because it is a weaker claim than a catalogued one.

PHASE 5Classify, filter, group — no network at all

Everything from here on is local. Duplicates are collapsed by ISBN, then by BID, then by a title-publisher-year signature, with the richest record kept as the base and poorer ones folded into its empty fields. Non-book media are dropped on what a record is, not what it is called — a documentary titled An ecology of mind: a daughter's portrait of Gregory Bateson once scored 0.67 against Steps to an Ecology of Mind and was reported as an edition of it. Sound recordings are kept: an audiobook is an edition of the text.

Year and publisher filters are applied here too, because SBN accepts neither as a query parameter. Then editions are grouped into works, sorted newest-first, bucketed by language, and the buckets ordered: the language you asked in, then the original's, then Italian, then English, then everything else by size, with unknown always last.

Grouping by any shared author

Keying a work on its first author's surname split Cent'anni di solitudine into four separate books: Open Library's comma-less “Gabriel García Márquez” reduces to marquez, SBN's “García Márquez, Gabriel” to garcia marquez, one record credits the translator Enrico Cicogna as sole author, and two put Gregory Rabassa ahead of the author. Editions are now merged into connected components by any shared author, transitively, with known translators subtracted first, and one token set being a subset of another counts as the same person.

Finally the header sentence is composed — once, in the pipeline, so that the CLI and the web UI cannot word the same claim differently. They already had, twice.

05The
gate

The gate: does this record belong?

The SBN author sweep returns everything the author has ever published. Without something to stop it, a lookup for one book returns a bibliography. The gate is _identifies(), and its rule is blunt: an edition is reported only if something ties it to this work.

WHY 0.6The calibration case

The threshold used to be 0.45, and one shared word passed. L'ordine delle notizie is a different book that shares two words with L'invenzione delle notizie. Because delle was missing from the stopword list while della was present, delle scored as a content word:

CandidateAffinity vs. L'invenzione delle notizieVerdict at 0.45
L'ordine delle notizie — a different book0.67accepted
the correct record0.43rejected

The wrong book beat the right one. No threshold placed anywhere between them saves you — the stopword list and the threshold are jointly load-bearing, and fixing one without the other brings it straight back.

Worth knowing how the score is computed, because it is not a fuzzy edit distance. Titles are normalised into sets of tokens — accents stripped, stopwords and single characters dropped — and similarity is the overlap penalised by the longer title: len(A & B) / max(len(A), len(B)).

WHY A SETA Dewey class is a subject, not an identity

This is the rule that makes the verdict structurally odd. García Márquez is 863.44 — and so is L'autunno del patriarca, and Il generale nel suo labirinto, and L'amore ai tempi del colera. Each an exact match, so no threshold separates them. They were all reported as editions of Cent'anni di solitudine.

The answer is not a better threshold. It is to look at the shape of the candidate set: if every record resting on Dewey alone carries the same normalised core title, the class is doing real work. If they carry several, the class is describing a shelf.

Dewey affinity itself is graded: 0.35 for an exact string match, 0.32 when the codes match after zero-padding is normalised (so Open Library's 070.09 and SBN's 070.9 compare equal), and 0.18 when they share a prefix of at least six characters and one is a prefix of the other. The six-character floor exists because a bare three-digit class means nothing — 306 is the whole of “culture and institutions”, which is how Attali's unrelated Chemins de sagesse was once presented as an edition of a 306.484 work.

Do not loosen

Two cases attack the gate from opposite sides and must be re-checked before touching it. L'ordine delle notizie is the calibration case — a false positive that outscored the truth. Quale socialismo, quale Europa is the existence case — Attali in 1977, same year as Bruits, a different book, and the only thing separating them is Dewey 335 against 780.07.

One scoping rule is easy to miss: the gate applies to title lookups only. An author search has no single work to identify, so everything by the author belongs in the answer by definition.

06The
premise

One host, two APIs, one wrong premise

Three sources, but four endpoints — because SBN is reached through two completely unrelated APIs that happen to share a hostname.

§4How a verified fact turned out to be wrong

The handoff's fourth section opens with the project's founding premise, presented as checked rather than assumed:

No free catalogue records a link between a translation and its original.

HANDOFF.md §4 — since struck through

Two of the findings supporting it are now struck out in the document itself, and both failed the same way.

The first: Open Library has no translation_of field. It does. The record that was checked, /works/OL15764295W.json for Rumori, has no such field because it is a work record — translation_of and translated_from live on editions. They are real and populated: Kafka a la platja carries translation_of: 海辺のカフカ and translated_from: /languages/jpn.

The second, and the one that mattered:

SBN does record the link, as a UNIMARC uniform-title authority — Titolo di opera in the OPAC. It is simply absent from the opacmobilegw JSON this project is built on, so six full records showed no trace of it and the conclusion was drawn from a hole in one API rather than from the catalogue.

HANDOFF.md §4

In both cases a field was declared absent after looking at the wrong kind of object: a work record instead of an edition record; one API instead of the catalogue. Six negatives read as proof. The generalised lesson is now a standing rule — check the record type before concluding a field is absent.

It was found by chasing the one book that nothing could reach. More Brilliant Than the Sun / Più brillante del sole shares no ISBN with its English editions, scores 0.0 on title similarity, and carries no Dewey class at all. Its SBN record was being found by the author sweep, fetched in full, and then discarded for lack of any signal. Pursuing that one failure surfaced the API that had held the answer the whole time.

The premise was not idle. The three inferring bridges, the Dewey scoring, the author sweep, the gate — the entire architecture exists to work around a gap that was only ever a gap in one JSON view.

Stale documentation

The README has not caught up. Lines 62 and 122 still assert that “SBN records carry no uniform title” and “records no original title”, two lines above a table that lists the uniform-title authority as the strongest mechanism available. HANDOFF §9 lists don't re-conclude that SBN records no original title under Do not regress. Trust the handoff, not the README, on this one point.

07The
traps

The traps

Read the handoff's trap list end to end and one shape repeats in nearly every entry: the system answers confidently and wrongly rather than failing. Nothing 400s. Nothing throws. You get a plausible answer about a different book.

Trap 01 · unknown parameters

SBN's gateway accepts exactly eight parameter names. Send a ninth and it is silently ignored and the unfiltered result set comes back. titolo= instead of title= does not error — it returns the whole catalogue's worth of hits, which downstream code treats as matches for your title. The containment is a whitelist, sbn.PARAMS, enforced in the single function every SBN call funnels through.

Trap 02 · the missing author

opac.work_for without an author answers, and the answer is a different book. Bare Rumori gives Russolo; bare The Essential Knuth gives a book on economics. Same failure shape as trap 01, on the other API.

Trap 03 · the language that lies

linguaPubblicazione is the only language signal, and it still lies: it sometimes names the language translated from. SBN record UBO4636099 is “Kafka on the shore / Haruki Murakami ; translated from the Japanese by Philip Gabriel”, London: Vintage, 2005 — catalogued GIAPPONESE. Believed, it put a lone 2005 Japanese edition under a header reading “first published 2002 in giapponese”.

The fix is deliberately weak, because there is no better signal to switch to. A record naming a translator while claiming the work's original language cannot be both, so its language becomes unrecorded rather than trusted. Disbelieved, never corrected.

Trap 04 · the country that is not a language

paesePubblicazione is a country and says nothing about language. Record CFI1172094 is an English Nineteen Eighty-Four published in Pesaro: INGLESE / ITALIA.

Trap 05 · facets that cannot filter

SBN returns facet counts and accepts none of them back as filters — lingua=, fq=, facet=, refine=, every form ignored. Filtering is the caller's job. Worse, the counts come from the author sweep, so they count the author's whole catalogue: for Per una economia positiva the facet reports francese 124 next to a result of exactly one Italian edition. The UI used to print those numbers, grey out the empty ones, and make the rest clickable — so the counts never agreed with the list beneath them and the grey entries advertised editions that did not exist.

Trap 06 · the data is dirty in specific ways

Non-sorting articles arrive wrapped in invisible C1 control characters ('\x88Il \x89disoriente'). Multiple Dewey codes run together with no separator ('616.89 (18.) PSICHIATRIA616.85 (19.) MALATTIE…') — and a letter-to-digit transition is not a word boundary, so a \b regex reads 616.85 as 85. Field names lie about their content: in localizzazioni the library name is in shelfmark and the city is in invNum. And translator evidence hides in free text — one record's only trace is the phrase “traduzione italiana a cura di…” inside a note.

Trap 07 · the stale server

Stop the server with pkill -f server.py. Not pkill -f "python3 server.py" — macOS reports the process as Python server.py, so that pattern matches nothing, and a stale instance keeps serving the modules it imported at startup while looking perfectly healthy. The handoff notes this wasted time twice. Same shape again: the wrong command reports success.

08When
it fails

When requests fail

A single lookup fans out over dozens of requests. Every helper caught its own failure and returned an empty list, so that one bad request could not sink the whole answer. That is a reasonable resilience choice with a fatal consequence: a dropped request and a genuinely empty catalogue produce byte-identical output.

Failing a third of the Open Library requests dropped English from 13 editions to 4, with no warning and the source still reporting ok. The user's long-standing complaint — “I only get Italian editions” — was diagnosed for a long time as a matching problem. It was a reporting problem.

A source is only ever downgraded from ok — a source already marked error or skipped keeps its stronger, more specific status. And the OPAC API notes its failures under the name SBN too, which is correct: it is the same catalogue.

The bug inside the fix

Tally defined __len__, which made an empty tally falsy. Helpers take tally=None to mean “don't record”, so every if tally: guard read a real-but-empty tally as absent — and the first failure was therefore never recorded, which meant the tally could never become non-empty, which meant the guards never switched on. The failure-reporting mechanism was itself silent. Adding __bool__ fixed it; guards now compare is not None.

BELOWWhat the network layer actually guarantees

(4, 15) — connect and read split deliberately, because an occasional 20-second connect stall to one Wikipedia host was single-handedly setting the cold-lookup time

Worth knowing

Any valid-JSON 200 is written to the cache, so a transient Solr error gets cached and re-raised for the full 24-hour TTL. There are a few such payloads sitting in .cache/ right now.

09The
answer

What comes back

One object, Report, carries everything: the mode (work or author), the query, the resolved cluster, an overview, editions bucketed by language code, the disambiguation choices, the per-source states, notes and errors. The CLI formats it as text, JSON or CSV. The server serialises it and adds two keys the browser needs — a map of language codes to display names, and the applied filters echoed back as a readable string, so a short list can explain itself.

The browser makes exactly one request. Everything after that — toggling a language, picking a work, clearing a filter — is a local re-render of the stored payload. Only an explicit Search again goes back to the network.

ANATOMYThe page, top to bottom

  • The publication history. The work's title, then a byline joining the authors, the origin phrase, and the totals — Gregory Bateson · first published 1972 in inglese · 37 editions in 6 languages.
  • Language bars on a shared time axis. One row per language, positioned by first year across a common range, so the gap between an original and its translations is something you see rather than work out. The original's row carries a red original tag.
  • A warning, if any source came back short. Red-ruled, with the per-source detail and a retry.
  • A chooser, only when several books share the title. Never offered when the answer is unambiguous.
  • A language filter that adds rather than narrows. Each active option puts a language back, and a line underneath says in words what is showing and how many editions in how many other languages are hidden.
  • The editions, hanging off a sticky rail carrying the ISO code, the language name and the count. Each row leads with year and publisher, because within one work every row repeats the same title and author — the year and publisher are the only fields that tell two editions apart.
  • Details, collapsed by default: physical description, translator, the libraries holding it grouped by city, shop links, and the catalogue record with the reasons it was matched.
  • The source footer — Wikidata ok · Open Library ok · SBN partial (2 request(s) failed).
The visual system

Two inks, borrowed from the red-and-blue bicolour pencil. Blue is the catalogue: links, and whatever you have selected. Red is a mark in the margin: which language is the original, which editions are first printings, a claim resting on inference rather than a catalogue record, a source that came back incomplete. If something is red, it is being pointed at. A third accent was removed deliberately so the reading stays unambiguous.

PHRASINGSentences the pipeline refuses to write

The origin phrase is composed once, in the pipeline, because the CLI and the web UI had already worded the same claim differently twice. Its branch structure encodes a rule rather than a format:

KnownSays
year + languagefirst published 1972 in inglese
year onlyfirst published 1972
language onlyoriginally in inglese, earliest edition found 1976
neitherearliest edition found 1976

A known original language is never paired with a fallback year — “first published 1976 in inglese” would take the year from an Italian edition and the language from the English original, and be simply false.

Three more refusals of the same kind. The original tag on a language row requires that row's years to actually reach the original year, or a giapponese 2005–2005 row carries it under a header saying “first published 2002”. When several books share a title, the byline names no author, because the aggregate is not any one of them. And if you pick a book from the chooser whose authors are not the ones the catalogues resolved, the header downgrades to “earliest edition found <year>” rather than reusing somebody else's first-publication date.

COPIESWhere to get one

Buy links are pure string templating — no network, no prices, no stock. Six retailers that were verified to return 200: IBS, Amazon.it, Feltrinelli and Mondadori as new; AbeBooks and Maremagnum as used. AbeBooks is omitted entirely without an ISBN, because its isbn= parameter is meaningless for a free-text query. Libraccio has no link at all: its search is an ASP.NET POST form, so no GET deep link exists.

The reasoning behind that restraint is worth keeping: no Italian retailer has a free stock or price API, scraping breaks and violates terms — and for an out-of-print book the honest answer is not a shop anyway. It is SBN's holdings list, which is why a record can tell you it is held by 229 libraries in 167 places.

Why lowering it hides bugs

Raising the budget and stopping Dewey from identifying a work alone were one change. The low budget had been hiding the Dewey defect: the wrong records score badly and were truncated away before anyone saw them, so the truncation was quietly doing the gate's job. That is the real reason the cap could not simply be removed, and the reason lowering it treats the symptom. Italian editions of Cent'anni di solitudine went 31 → 57, with the wrong books gone.

Overflow is never silent: a note records how many candidates existed and that only the top N were fetched.

CACHEWhy it is load-bearing, not an optimisation

A cold lookup takes 35–50 seconds; a repeat takes about 0.03. Responses are keyed by URL plus sorted parameters, hashed, and written as flat JSON files with a 24-hour TTL. POSTs are keyed on the URL plus the body, so a GET and a POST to the same URL cannot collide. A corrupt entry falls through and refetches; a cache write failure is swallowed, because a read-only cache directory must not break a lookup. Cache hits are served regardless of network state, so a flaky connection degrades to stale-but-useful.

One lookup fans out over dozens of requests — 15 or more full.json calls alone. Without the cache the tool is unusable to iterate on and impolite to a public catalogue. Delete .cache/ to force fresh data.

Most of the cold latency is not SBN. It is dominated by an intermittent connect stall to one Wikipedia host: curl is consistently 0.3 seconds while one Python process saw 37 seconds and another 0.28 for the identical request. Parallelising around it does not help — it is the critical path. The split timeout is the mitigation: stall fast, fail fast, retry.

How to assert

Edition counts drift as the catalogues are updated. Assert on structure — both languages present, exactly one Italian, N choices, correct language classification — never on exact totals.

The two cases the documentation singles out are not in this table at all. They are the negative ones, the records that must stay out: L'ordine delle notizie and Quale socialismo, quale Europa, both described in §05. Neither can be loosened without re-checking the other.

The cheapest available improvement is named precisely in the handoff: pytest coverage for the pure functions — matching.py, langs.py, the sbn.py parsers, and in the pipeline _dewey_affinity, _identifies, _dewey_discriminates, _assign_groups, _span_is_original and _origin_phrase. All deterministic. None of them touch the network.
